= Validation

[[validation.assigning-validators]]
== Assigning Validators

To register a `Validator` instance, implement `RepositoryRestConfigurer`, override `configureValidatingRepositoryEventListener`, and call `addValidator` on the `ValidatingRepositoryEventListener`, passing the event on which you want this validator to be triggered and an instance of the validator. The following example shows how to do so:

====
[source,java]
----
@Override
public void configureValidatingRepositoryEventListener(ValidatingRepositoryEventListener v) {
  v.addValidator("beforeSave", new BeforeSaveValidator());
}
----
====

[[validation.events]]
== Validation Events

A validator runs when its event is published and validates the object the event carries. For link events, that is the parent entity. See xref:events.adoc#events.lifecycle[Event Lifecycle and Object State] for when each event fires and which object it carries.

The following table maps event names to events:

[cols="1,1", options="header"]
|===
| Event Name | Event

| `beforeCreate` | `BeforeCreateEvent`
| `afterCreate` | `AfterCreateEvent`
| `beforeSave` | `BeforeSaveEvent`
| `afterSave` | `AfterSaveEvent`
| `beforeLinkSave` | `BeforeLinkSaveEvent`
| `afterLinkSave` | `AfterLinkSaveEvent`
| `beforeDelete` | `BeforeDeleteEvent`
| `afterDelete` | `AfterDeleteEvent`
|===

`BeforeLinkDeleteEvent` and `AfterLinkDeleteEvent` do not trigger validation.
